# v8 社会記憶アーキテクチャ

この版では「Discordから学ぶもの」を3層に分離します。

1. **会話経験**: 返信そのものが良かったか、悪かったか。
2. **社会記憶**: ユーザーの観測可能な話し方・活動量、ユーザー間の接点、サーバー/チャンネルの傾向。
3. **LLM学習**: 安定して良かった返信例だけを重みの学習に回す。

## 重要な設計方針

- ユーザーの「性格」を断定しません。`short / normal / long / question / casual` など、発言から直接観測できる傾向だけを統計化します。
- 「知名度」は世界的な評判ではなく、**そのサーバー内の influence_score** です。発言数、接点数、返信/メンションを対数圧縮して計算します。
- ユーザー同士の関係は有向グラフとして保存し、返信・メンション・接触頻度を蓄積します。
- サーバーは発言数、活動時間、話題分布を集計します。
- 変化の速い情報（知名度、最近の関係、最近の話題）はモデルの重みに焼き付けず、**返信直前にDBから取得してプロンプトへ注入**します。
- 長期的に良い応答例だけを `experience_core` → `discord.jsonl` → fine-tuning に回します。

## DB

`data/social_memory.db` に以下を保存します。

- `user_profile`: サーバー別ユーザー統計
- `relation`: ユーザー→ユーザーの関係エッジ
- `server_profile`: サーバー全体の統計
- `channel_profile`: チャンネルごとの統計

個人情報を推測するための分類器は入れていません。医療、政治、宗教、性的指向などのセンシティブ属性を「性格」として推定する設計にもしていません。

## 返信時の流れ

```text
Discord message
   │
   ├─→ 会話ログ / ExperienceCore
   │
   └─→ SocialMemory
          ├─ user profile
          ├─ user-user relations
          ├─ server profile
          └─ channel profile
                 │
                 ▼
        relevant social context
                 │
                 ▼
              LLM
                 │
                 ▼
              reply
                 │
                 ▼
       反応を観測 → Experience + relationship
                 │
                 ▼
      良い経験だけを再学習データへ
```

## 注意

DiscordのユーザーIDは「個人の属性を推測するため」ではなく、同一人物をサーバー内で継続的に区別するために使います。実運用では、サーバー管理者の同意、利用者への告知、保存期間、削除/オプトアウト機能を用意することを推奨します。
